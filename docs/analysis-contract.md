# 分析资料与解释边界

## 标签与选择
items 中 project 为项目归属，available_at 决定当时可用特征。positive_reports 只表示已经确认的正例，上报概率未知；未出现不等于负例。audits 中 probability 是已知概率抽取，queue 是人为优先复核；只有前者记录 inclusion_probability。audit_outcome 是复核结果，不是输入特征。
## 可部署解释
候选应能在当时可见特征上训练和排序，按项目与时间防泄漏。若总体正例比例或校准概率依赖不可检验假设，需给出假设及敏感性，不能声称从未标注自动恢复真实负例。队列与模型版本配套；回流数据不得改变已有独立核查结果的用途。
## 检查情形
analysis_cases 有随机报正、依特征报正、某组从不报正和独立概率核查。可在有完整合成真值但不暴露给训练端的检验里比较基准，不能要求真实业务未知标签有准确率。只使用队列核查时，应限制总体性能和比例声明。
