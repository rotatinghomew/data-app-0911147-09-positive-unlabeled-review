# 分析资料与解释边界

## 标签与选择
items 中 project 为项目归属，available_at 决定当时可用特征。positive_reports 只表示已经确认的正例，上报概率未知；未出现不等于负例。audits 中 probability 是已知概率抽取，queue 是人为优先复核；只有前者记录 inclusion_probability。audit_outcome 是复核结果，不是输入特征。

## 学习视图（app/review.py）
标签状态只有四类：已确认上报正例、核查确认正例、核查确认负例、未核实。未核实记录不充当负例，任何“把未标注批量当负例”的准确率都被抑制（suppressed_metrics）。训练与排序只使用截止时可用特征；项目编号不作为特征；截止后才可用的记录不评分不排队。上报与核查结果冲突的记录排除出训练并在 conflicts 中列出。

## 选择假设与可识别性
排序分数 g(x)=P(被上报|特征) 是 PU 非传统分类器，SCAR（上报率与特征无关）下与风险同序，因此排序本身不需要点估计 c。比例与概率结论依赖假设：SCAR 下仅区间可识别（c ∈ [max g, 1]，比例 ∈ [P(被上报), P(被上报)/max g]）；Elkan-Noto 的 e1 点估计只在正负例近似可分时无偏，特征重叠时系统性低估上报率、高估比例，因此只作为带标注的参考值给出。分层假设（SAR，上报率只随批次×团队群体变化）下 c_群体 由概率核查估计；无核查覆盖或从未上报的群体不可识别，其记录不给出模型概率。

## 核查的用途
概率核查是唯一不依赖上报机制的总体估计来源（Hájek 估计与线性化标准误），用于检验 SCAR 含义下的期望正例数、估计群体上报率、判断队列价值；它只代表其抽样框。队列核查是选择性样本，只描述被挑中记录。两者不合并为同一份验证集。无概率核查时，总体比例、校准与队列价值结论一律为 null 并说明原因。

## 队列与回流
review_queue 按每天可复核数量生成：scar 假设给排序分与逐项概率区间，stratified 假设给分层概率；无可靠概率的记录列于末尾并标记，由业务决定是否复核。标签回流后，feedback 区分三件事：模型学到什么（系数与队列变化）、总体判断为何变化（锚定独立概率核查，而非队列回流标签）、哪些群体仍不适合给出可靠概率（群体可靠性状态）。队列核查回流只改变排序模型，不改变总体比例估计。

## 可部署解释
候选应能在当时可见特征上训练和排序，按项目与时间防泄漏。若总体正例比例或校准概率依赖不可检验假设，需给出假设及敏感性，不能声称从未标注自动恢复真实负例。队列与模型版本配套；回流数据不得改变已有独立核查结果的用途。

## 检查情形
analysis_cases 有随机报正、依特征报正、某组从不报正和独立概率核查。可在有完整合成真值但不暴露给训练端的检验里比较基准，不能要求真实业务未知标签有准确率。只使用队列核查时，应限制总体性能和比例声明。random_positive_oracle 的 oracle_truth 不进入任何训练或排序输入，仅用于检验可识别区间是否覆盖真值。
